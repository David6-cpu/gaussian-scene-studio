# 水体意图 v2 验证

实现日期：2026-10-04；最终回归：2026-10-07。**固定样例的水体意图提取通过；原句对应的河道几何仍待匹配，最终河流画质未通过。**

## 解决的问题

“河岸上放一些低矮草丛和石头”表达了需要河流，但没有指定数值水位。此前把缺少水位与无水混在一起，无法准确说明下一步需要解决什么。v2 将水体意图与可构建的几何参数分开，应用于显式试用入口 `/?review=1&planner=3b`。

## 已实现

- `water.mode` 区分 `river`、`surface`、`none`、`unspecified`；`explicitLevel` 只保存原文给出的数值。新记录中 `null` 表示未给水位，旧记录仍按原合同解释。
- 河流意图没有水位时保留为待处理，不补 0，也不要求用户改写原句。明确无水或给定数值后，才进入后续检查。
- 页面区分“描述需要河流”和“水面位置尚未验证”。待处理时不能启动选材、替换场景或写入历史。
- 人工修改单独保存，不覆盖原始模型需求；v2 审阅记录独立存储，导入时重新编译和校验摘要，旧 v1 不自动迁移。
- 继续保留可撤销预览、迟到响应隔离、GPU 失败回退、并发保存和存储失败提示。

## 有限真实模型验证

使用既有 Qwen2.5-3B-Instruct Q4_K_M，共进行了 **10 次真实需求提取请求**：首轮 5 次，随后只修正一次提示，再用相同的 5 条输入复验。首轮出现水体分类、单位和来源错误，失败结果保留；没有通过换输入或只报告成功请求来筛选结果。

| 原样复验输入 | 修正后水体输出 | 当前含义 |
|---|---|---|
| 河岸上放一些低矮草丛和石头 | `river`，无数值 | 河流意图明确，几何待匹配 |
| 干涸河床，不放水，放4丛低草 | `none`，无数值 | 无水需求可进入下一步检查 |
| 河岸上放一些低矮草丛和石头，不放水 | `none`，无数值 | 无水明确，石头仍需主动处理 |
| 放一些低矮草丛和石头 | `unspecified`，无数值 | 需要明确水体选择 |
| 河岸水位-0.025，2组石头、4丛低草 | `river`，`-0.025` | 保留数值，仍需选材与构建检查 |

修正后五条的单位等字段通过本组检查，提取耗时约 1.6–2.3 秒。冲突输入“水位0，不放水”在推理前被拦截。以上只证明这组固定样例；**本阶段没有真实第二阶段选材调用，也没有完成原句到场景的真实 AI 闭环。**

模型停止后，Chrome 重放已保存的真实提取响应，验证摘要和待处理状态。另行主动选择手动无水流程，验证了取消不写记录、使用后恰好新增一条 v2、旧 v1 字节保持；手动流程没有计入模型成功率。
